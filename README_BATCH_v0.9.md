# ResumeMatch AI v0.9 — пакетное сопоставление резюме

## Что добавлено

- Сравнение **до пяти PDF/DOCX/TXT резюме с одной вакансией** за один запуск интерфейса.
- Однократное LLM-извлечение требований вакансии (или повторное использование извлечения, если оно уже было выполнено для той же вакансии).
- Последовательное LLM-извлечение фактов из каждого резюме — только после **отдельного согласия** на передачу данных в OpenAI.
- **Необязательная** платная проверка датированных периодов работы и обязанностей для каждого резюме через уже существующий v0.5.
- Локальный серверный пересчёт доказательной матрицы v0.7 для **каждого оригинала отдельно** (`POST /api/batch/compare`).
- Сводная таблица *требование × кандидат*; отдельные раскрываемые доказательства и проверенные цитаты.
- Экспорт **отдельного PDF для каждого резюме** через уже существующий v0.8 — без дополнительных вызовов OpenAI.

Порядок кандидатов совпадает с порядком выбранных файлов. **Нет автоматического рейтинга, решения о найме и итогового балла пригодности.** Дословное упоминание не доказывает практические навыки, отсутствие сведений не означает отсутствие квалификации. Смысловое соответствие, корректность длительности работы и решения остаются за человеком.

## Установка поверх рабочей v0.8

Путь проекта на Windows: `F:\MATRIX`.

1. Убедитесь, что изменения v0.8 опубликованы на GitHub или сохранены локально. Не удаляйте `.env`.
2. Распакуйте `ResumeMatch_AI_Batch_v0.9.zip` в корень `F:\MATRIX`, сохраняя подпапки. Архив **не содержит** готового `app/main.py` или `static/index.html` и не заменяет их напрямую.
3. В PowerShell выполните:

   ```powershell
   cd F:\MATRIX
   .\.venv\Scripts\python.exe scripts\install_batch_v09.py
   .\.venv\Scripts\python.exe -m pytest -q
   ```

4. Запустите:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
   ```

5. Откройте http://127.0.0.1:8765 и обновите страницу через `Ctrl+F5`.

Установщик делает резервные копии `app/main.py.before_batch_v09`, `static/index.html.before_batch_v09`, `.gitignore.before_batch_v09` и `README.md.before_batch_v09` **перед первым изменением**. Эти файлы исключаются из Git. Повторный запуск не дублирует код.

## Как проверить без реальных персональных данных

1. В верхней форме загрузите любое тестовое резюме, выберите режим **Демо**, нажмите «Проанализировать резюме».
2. В разделе **«Пакетное сравнение резюме · v0.9»** выберите вакансию **«Python Backend / AI-разработчик — проверка стажа»**.
3. Выберите из `samples/` три **вымышленных** файла:
   - `batch_candidate_backend.txt`
   - `batch_candidate_django.txt`
   - `batch_candidate_no_fastapi.txt`
4. Установите согласие на отправку в OpenAI. **Сначала оставьте дополнительный анализ стажа выключенным**, чтобы уменьшить затраты.
5. Нажмите «Сопоставить резюме». Должна появиться сводная таблица с отдельными колонками по каждому кандидату, подробными цитатами и кнопками PDF.
6. После базовой проверки можно повторить с галочкой анализа стажа. Это уже дополнительные платные запросы.

**Важно:** интернет и оплачиваемый OpenAI API нужны для фактического LLM-извлечения. Автоматические тесты `pytest` выполняются **офлайн** и не списывают деньги за OpenAI.

## Стоимость и приватность

При `N` резюме: до `1 + N` последовательных вызовов OpenAI (один раз для вакансии, один раз для каждого резюме). Если извлечение вакансии уже доступно и совпадает с выбранной вакансией, вызов вакансии повторно не делается. При дополнительном анализе стажа — обычно ещё до `2 × N` платных вызовов. Точное число и стоимость зависят от ответов модели и текущих тарифов OpenAI. **При ошибке частично завершённые обращения тоже могут тарифицироваться.**

Резюме не записываются пакетным модулем на диск или в БД и обрабатываются в памяти текущего запроса. Исходные тексты резюме отправляются только в старые, уже используемые маршруты `/api/llm/resume` и `/api/llm/experience-match` по отдельному согласию пользователя. Исходный текст вакансии передаётся в `/api/llm/vacancy`. Оба вида данных могут содержать персональные сведения; загружайте только документы, которые вправе обрабатывать. Модель в облаке может обрабатывать отправленные данные по политике выбранного сервиса. Не пересылайте PDF-отчёты без согласия владельцев резюме.

Новый маршрут `/api/batch/compare` **не обращается к OpenAI** и не сохраняет документы. Он получает исходники и уже извлечённые факты; сервер **повторно проверяет цитаты** и не доверяет выставленному клиентом флагу `source_verified`. Доказательства проверяются отдельно по каждому резюме, без смешивания между кандидатами. При явных отрицаниях контекст строки не засчитывается как подтверждение опыта.

## API

**`POST /api/batch/compare`**, `multipart/form-data`:

| Поле | Тип | Обязательное |
|---|---|---|
| `resumes` | 1–5 файлов, повторяемое поле | Да |
| `resume_extractions` | JSON-массив извлечений резюме в порядке файлов | Да |
| `vacancy_source` | JSON-объект `description_text` и `key_skills` | Да |
| `vacancy_extraction` | JSON-объект LLM-извлечения вакансии | Да |
| `experience_results` | JSON-массив результатов v0.5 или `null` | Нет |
| `candidate_labels` | JSON-массив подписей (без ФИО по умолчанию) | Нет |

Ответ содержит `candidates` с отдельными матрицами, `comparison` с сопоставлением по требованиям, флаг `automated_ranking: false`, `cloud_calls: 0`. Заголовок `Cache-Control: no-store`.

Ограничения: не более пяти файлов и 6 МБ на каждый, не более 500 000 символов в агрегированных исходных JSON. Ошибка в одной отправке прерывает текущую клиентскую обработку, но уже выполненные платные вызовы OpenAI могут учитываться провайдером. Данные результатов видны только в текущей вкладке до обновления страницы; истории пакетных обработок нет.

## Ограничения v0.9

- Отдельные семантические и FAISS/RAG-проходы для **каждого** резюме в пакетном режиме **не выполняются автоматически**; их можно запустить в основном однодокументном режиме.
- Проверка навыков основана на упоминаниях и подтверждённых цитатах, а не на тестировании компетенции.
- Числовые требования к стажу без дополнительной проверки показываются как «проверка не запускалась».
- В этом обновлении нет очереди фоновых задач, сохранения пакетов или повторов запросов после ошибки.
