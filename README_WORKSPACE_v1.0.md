# ResumeMatch AI v1.0 — локальная история и управление данными

Пакет устанавливается **поверх рабочей v0.9**. Исходные PDF/DOCX/TXT не сохраняются. В SQLite сохраняются **только по отдельному согласию** зашифрованные снимки результатов и карточки кандидатов/вакансий. Это **локальный однопользовательский режим**, не production-сервис для общедоступного URL.

## Установка на Windows / PowerShell

1. Убедитесь, что `git status` чистый, и сделайте резервную копию проекта. **Не распаковывайте без проверки поверх незакоммиченных изменений.**
2. Распакуйте архив в `F:\MATRIX`, сохранив каталоги `app/`, `assets/`, `scripts/`, `tests/`.
3. Выполните:

```powershell
cd F:\MATRIX
.\.venv\Scripts\python.exe scripts\install_workspace_v10.py
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

4. **Локально** сгенерируйте *два разных секрета* (не копируйте их в чат и GitHub):

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
.\.venv\Scripts\python.exe -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Первый — для `RESUMEMATCH_WORKSPACE_TOKEN`, второй — для `RESUMEMATCH_HISTORY_KEY`.

5. Откройте `F:\MATRIX\.env` и **добавьте** (не заменяя существующие значения OpenAI):

```dotenv
RESUMEMATCH_WORKSPACE_TOKEN=<секрет_из_первой_команды>
RESUMEMATCH_HISTORY_KEY=<секрет_из_второй_команды>
RESUMEMATCH_RETENTION_DAYS=30
RESUMEMATCH_DB_PATH=data/resumematch_history.sqlite3
```

Замените плейсхолдеры на сгенерированные значения. `.env` должен оставаться вне Git. **Сохраните ключ Fernet в надёжном менеджере секретов**: после потери ключа историю невозможно расшифровать. При смене ключа старая база не откроется; не меняйте его без продуманной миграции.

6. Проверка и запуск:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

В интерфейсе найдите **«Кандидаты, вакансии и история · v1.0»**, введите только **токен доступа** (не ключ шифрования!), откройте историю. Сделайте обычный v0.8-отчёт или v0.9-пакет, подтвердите согласие на локальное хранение и сохраните снимок соответствующей кнопкой. Можно добавлять/редактировать/удалять карточки, открывать и удалять архивы.

## Что именно сохраняется

| Объект | Поля | Условия |
|---|---|---|
| Кандидат | Имя/метка, необязательная заметка | Зашифровано, пока не удалите вручную |
| Вакансия | Заголовок, описание, навыки | Зашифровано, пока не удалите вручную |
| Анализ | Текстовая матрица, цитаты, итог, ссылки на карточки | Шифрование Fernet, TTL 30 дней по умолчанию |
| Исходный файл | **Ничего** | PDF/DOCX/TXT не записываются на диск базой истории |

Архивы истекают через 1–365 дней (`RESUMEMATCH_RETENTION_DAYS`), удаление выполняется при следующем обращении к истории. При удалении кандидата/вакансии связанные архивы также удаляются. Карточки, созданные автоматически при сохранении пакета, **не удаляются** при истечении архива: удалите их вручную, если они больше не нужны.

История — **архивный снимок**. При открытии не происходит новая верификация цитат по исходному резюме. Итоговые кадровые решения остаются за человеком. Снимки не становятся новыми доказательствами квалификации из-за факта сохранения.

## API

Маршруты `/api/workspace/*` требуют заголовок `X-Workspace-Token`:

- `GET/POST /candidates`, `PUT/DELETE /candidates/{id}`
- `GET/POST /vacancies`, `PUT/DELETE /vacancies/{id}`
- `GET/POST /archives`, `GET/DELETE /archives/{id}`
- `POST /purge`

При сохранении отчёта/пакета UI повторно вызывает **локальные** проверки `/api/report/preview` или `/api/batch/compare`, затем делает отдельный защищённый запрос на сохранение. На этапе формирования истории OpenAI API **не вызывается**.

## Границы безопасности

- Система предназначена исключительно для локального использования на `127.0.0.1` одним доверенным пользователем.
- Токен защищает **только новые** `/api/workspace/*` маршруты. Старые `/api/analyze`, `/api/llm/*`, `/api/batch/*` и т.д. не получают авторизацию от этого обновления. **Нельзя открывать существующий сервер в публичный интернет** без сквозной аутентификации, TLS, CSRF-защиты, журналирования доступа и других мер.
- Шифрование применяется к полям, сохранённым в SQLite. Это не замена шифрованию диска Windows (BitLocker) или защите резервных копий. SQLite и ОС могут сохранять файлы/снимки при резервном копировании.
- API принимает снимок анализа из браузера и хранит его как **данные пользователя**. В нём нельзя утверждать, что подлинность результата доказана одной лишь записью в историю.
- Если компьютер общий, закройте доступ кнопкой «Закрыть доступ», блокируйте сеанс Windows и не оставляйте `.env` доступным другим пользователям.
- Перед публикацией Git убедитесь, что `.env`, каталог `data/` и резервные копии исключены. Не используйте реальные резюме в демофайлах репозитория.
- Удаление из SQLite не гарантирует стирания резервных копий, облачной синхронизации диска или внешних систем OpenAI; организуйте удаление в соответствии с вашими обязательствами по защите данных.

## Ограничения версии

Нет отдельных пользовательских ролей, многоарендной архитектуры, перезапуска анализа из сохранённого PDF (оригиналы не сохраняются), миграций БД и многопользовательской авторизации. Это функциональный **локальный v1.0**, а не готовый SaaS для размещения в интернете.
