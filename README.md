ResumeMatch AI
Интеллектуальный анализ резюме и вакансий с проверяемыми выводами
ResumeMatch AI — демонстрационное веб-приложение на Python / FastAPI, которое извлекает сведения из резюме и вакансий, строит матрицу соответствия и показывает исходные фрагменты текста, на которых основан каждый вывод.

Проект сочетает локальные правила сопоставления и опциональный анализ через OpenAI API. Основной принцип: не считать отсутствие подтверждения доказательством отсутствия навыка.

Возможности
Функция	Что реализовано
Обработка документов	Извлечение текста из PDF, DOCX, TXT; при необходимости — локальный OCR сканированных PDF
Источники вакансий	Встроенные синтетические вакансии и поиск через официальный API hh.ru

Проверка доказательств	Для фактов сохраняются source_text, source_verified и, когда применимо, страница/поле документа
LLM-матрица	Сопоставление обязательных и желательных навыков по подтверждённым извлечённым данным
Семантический анализ	Отдельная LLM-проверка возможных смысловых совпадений с выводом предварительного результата
Анализ опыта	Извлечение датированных периодов работы, консервативный подсчёт месяцев без двойного учёта пересечений
Сопоставление обязанностей	Предложения LLM с подтверждающими фрагментами и необходимостью ручной проверки
Экспорт	Просмотр и скачивание результатов в JSON


Как интерпретировать результаты
- Точное совпадение означает, что навык явно найден в подтверждённых данных; это не оценка уровня владения технологией.
- Нет подтверждения означает, что в обработанных фрагментах резюме не найдено достаточного основания, а не то, что кандидат не обладает навыком.
- Семантическое совпадение — предложение LLM для проверки человеком. Оно показывается отдельно от точных совпадений.
- Подтверждённая цитата означает, что фрагмент source_text дословно присутствует в обработанном тексте. Это не гарантирует, что модель правильно интерпретировала смысл.
- Стаж по технологии оценивается консервативно по датированным периодам, с которыми технология связана в извлечённых данных. Связь технологии с конкретной должностью требует проверки.
- Процент соответствия основан на навыках и не является вероятностью трудоустройства. Стаж и обязанности не добавляются автоматически к проценту навыков.

Локальное сопоставление и OpenAI-анализ разделены: обычный анализ можно выполнять без API-ключа и без отправки резюме в OpenAI. Семантический анализ и проверка опыта запускаются отдельно.
Технологии
Backend: Python, FastAPI, Pydantic, Uvicorn, HTTPX.

AI / обработка текста: OpenAI API (Structured Outputs), PyMuPDF, python-docx, Beautiful Soup; опционально pytesseract.

Frontend: HTML, CSS, JavaScript.

Тестирование: pytest.
Установка и запуск
Ниже пример для Windows PowerShell. Требуются Python и Git.
# Клонировать проект
git clone https://github.com/Stanislav20221/ResumeMatch-AI-.git
cd ResumeMatch-AI-

# Создать окружение и установить зависимости
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# Создать локальный файл настроек
Copy-Item .env.example .env

# Запустить веб-приложение
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
Интерфейс: http://127.0.0.1:8765
Swagger API: http://127.0.0.1:8765/docs

Для первого запуска достаточно загрузить samples/demo_resume.txt, выбрать демонстрационные вакансии и выполнить обычный анализ.
Настройка OpenAI (необязательно)
Откройте локальный .env и заполните параметры:
OPENAI_API_KEY=YOUR_OPENAI_API_KEY
OPENAI_MODEL=gpt-4.1-mini
Не добавляйте .env в Git и не вставляйте рабочие ключи в примеры или скриншоты. Запросы к OpenAI тарифицируются отдельно. В интерфейсе предусмотрено согласие на передачу данных, а дополнительные этапы анализа запускаются отдельно.
Поиск вакансий hh.ru (необязательно)
Для работы с hh.ru используется официальный API. Настройте контактный User-Agent по требованиям API, например в .env через HH_USER_AGENT с вашим настоящим контактным адресом. При ограничениях или недоступности API можно использовать встроенные демоданные.
OCR для сканированных PDF (необязательно)
Для распознавания сканов требуется отдельная установка Tesseract и языковых данных; в .env можно включить ENABLE_OCR=1. Без этого обычные PDF с текстовым слоем, DOCX и TXT обрабатываются без OCR.
Как проверить анализ опыта
1. Загрузите samples/demo_resume_experience_positive.txt.
2. Выберите деморежим и вакансию «Python Backend / AI-разработчик — проверка стажа».
3. Выполните основной анализ, затем — LLM-извлечение данных из резюме и вакансии (с согласия пользователя).
4. Запустите «Проверить стаж и обязанности (OpenAI)».
5. Сравните требования по Python и FastAPI с документированными месяцами; проверьте цитаты, интервалы работы и предложения по обязанностям.
Для синтетического позитивного сценария: Python — требование от 36 месяцев, FastAPI — от 24 месяцев. В тестовых данных присутствуют пересекающиеся периоды занятости; система не должна суммировать такие месяцы дважды. Эти данные созданы для проверки поведения алгоритма, а не для оценки реального кандидата.
API

Тестирование
.\.venv\Scripts\python.exe -m pytest -q
Проверки охватывают локальное сопоставление, структуру извлечённых фактов, семантическую оценку, датированные периоды, пересечения и сценарии, в которых подтверждения недостаточно. Для офлайн-тестов рабочий OpenAI-ключ не требуется.
Конфиденциальность и ограничения
- В локальном режиме резюме не передаётся на hh.ru или в OpenAI; в hh.ru отправляются параметры поиска вакансий.
- Для LLM-операций документ или извлечённые данные отправляются во внешний OpenAI API только после согласия пользователя. Не используйте реальные персональные данные без соответствующих оснований и согласий.
- В приложении нет постоянной базы хранения резюме. Это локальный прототип, не готовый публичный сервис с авторизацией и защитой персональных данных.
- Привязка цитаты к документу проверяет наличие текста, но не истинность или корректность выводов модели.
- Векторный поиск, эмбеддинги и полноценный RAG/FAISS-пайплайн пока не реализованы. Наличие навыков RAG и FAISS в деморезюме не означает, что само приложение использует эти технологии.
- LLM-предложения требуют экспертной проверки; система не принимает кадровые решения автоматически.
Дальнейшее развитие
- Масштабирование retrieval/RAG на большие корпуса документов и постоянные индексы.
- Сводная матрица навыков, датированного стажа и обязанностей с ручным подтверждением решений.
- Дополнительные тесты качества извлечения и сложных случаев: неоднозначные даты, отрицания, неполные резюме.
- Экспорт проверенной матрицы в XLSX/PDF, обезличивание и журнал изменений.
Статус проекта: учебно-практический MVP для демонстрации LLM-интеграции, структурирован
