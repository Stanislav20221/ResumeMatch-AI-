# ResumeMatch AI — структурирование резюме и матрица соответствия вакансий

Локальный демонстрационный MVP для портфолио: принимает резюме PDF/DOCX/TXT,
извлекает явно упомянутые навыки с фрагментами-основаниями (`source_text`),
получает первые вакансии из официального API hh.ru, превращает их в JSON
и строит проверяемую матрицу сопоставления по навыкам.

**Статус:** работающий локальный MVP без LLM и без FAISS. Алгоритм правила + словарь
синонимов, поэтому это *не* полный semantic RAG и *не* извлечение всех сущностей.
Предназначен как доказуемая основа для следующих этапов (LLM, embeddings, OCR, валидация).

## Быстрый запуск (Windows PowerShell)

```powershell
cd C:\Projects\resumematch-ai  # замените на путь к вашей пустой папке
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Открыть **http://127.0.0.1:8000** в браузере. Для начала загрузить `samples/demo_resume.txt`
и выбрать **Демо**. API-интерфейс Swagger: **http://127.0.0.1:8000/docs**.

На Linux/macOS активируйте `source .venv/bin/activate` вместо PowerShell-команды.

## Доступ к реальным вакансиям hh.ru

Используется **официальный API**, а не HTML-скрейпинг:
- `GET https://api.hh.ru/vacancies?text=...&per_page=...&page=0`
- `GET https://api.hh.ru/vacancies/{id}` для подробного описания.

Перед запуском установите `User-Agent` со **своим реальным контактным адресом**.
В PowerShell (подставить настоящий адрес):

```powershell
$env:HH_USER_AGENT = 'ResumeMatchAI/0.1 (contact: you@yourdomain.ru)'
```

Выберите в интерфейсе «hh.ru API — реальные вакансии». Система отправляет на
hh.ru **только поисковую строку**, код региона и параметры поиска, **не резюме**.

> Важно: поиск без OAuth может запрашивать капчу или ограничивать доступ. При
> HTTP 403/429 приложение показывает честную ошибку, **не подменяет результаты**
> вымышленными вакансиями. При необходимости используйте демо или официальный
> способ авторизации hh.ru. Пожалуйста, соблюдайте правила API и не обходите ограничения.

Документация: https://api.hh.ru/openapi/redoc

## Как выглядит JSON

```json
{
  "resume": {
    "filename": "demo_resume.txt",
    "skills": [
      {"name": "Python", "matched_text": "Python", "source_text": "Python, FastAPI, ...", "page": null}
    ]
  },
  "matches": [
    {
      "score_percent": 75,
      "matrix": [
        {
          "requirement": "Python",
          "status": "matched",
          "vacancy_source_text": "Python",
          "vacancy_source_field": "key_skills",
          "resume_source_text": "Python, FastAPI, ...",
          "resume_page": null
        }
      ]
    }
  ]
}
```

Фрагмент выше — **схематический**, реальные данные содержат все поля ответа.
В интерфейсе есть кнопка **«Скачать полный JSON»**.

## Подсчёт процента

`score_percent = round(100 * число_подтверждённых_навыков / число_распознанных_требуемых_навыков)`.

- Подтверждение означает лишь **буквальное упоминание** навыка или его алиаса в резюме;
  доказательством является исходная строка документа.
  Ссылки на фрагменты проверяются на принадлежность исходному тексту. Не оценивается глубина владения.
- Система не делает вывод «не умеет» при отсутствии навыка, а пишет «нет подтверждения».
- Если словарь не распознал требования, процент равен `null` — не ложные 100%.
- Дополнительные текстовые требования вакансии сохраняются как
  `other_requirements_for_review` и требуют ручного анализа.
- Похожие технологии не приравниваются автоматически: `FastAPI` не значит `REST API`,
  `FAISS` не значит `RAG`, если нет явного упоминания.
- **Этот процент — не вероятность найма.** В MVP нет LLM, embeddings, рекрутингового
  моделирования, извлечения стажа и нормализованного сравнения опыта.

## PDF, DOCX и OCR

- PDF: PyMuPDF, постраничный текст (возвращается номер страницы для цитаты).
- DOCX: python-docx, параграфы и ячейки таблиц (без точных номеров страниц).
- TXT: UTF-8. Объём одного файла до 6 МБ, PDF — до 35 страниц.
- Сканированный PDF: опциональный **локальный** OCR через `pytesseract`. Нужен
  установленный Tesseract и языковые пакеты `rus`, `eng`.
  В PowerShell включить: `$env:ENABLE_OCR = '1'`.
  Для Windows при необходимости установить Tesseract в `PATH`.
- Изображения страниц с неполным текстовым слоем могут требовать отдельной OCR-обработки.

## Безопасность и персональные данные

- Приложение запускается на **127.0.0.1**, не открывает публичный порт.
- Резюме обрабатывается локально, без постоянного хранения в БД/логах
  и без отправки в сторонние LLM. Загрузка больших файлов может использовать
  временный системный файл FastAPI/Starlette.
- Весь JSON возвращается браузеру; скачивание JSON инициируется в браузере.
- Не публикуйте результаты анализа с персональными данными резюме на GitHub.
- Не выставляйте приложение в интернет без авторизации, ограничений доступа и правил
  обработки персональных данных.

## Следующие этапы

1. LLM extraction с Pydantic-схемами: стаж, образования, требования, желательные навыки.
2. Трёхуровневое сопоставление: точное, нормализованное/семантическое, LLM-анализ сложных требований.
3. FAISS/RAG по фрагментам резюме и вакансии; обязательные цитаты на фрагменты и
   автоматическая проверка `source_text` по исходному тексту.
4. Выделение структуры резюме по разделам, OCR отдельных страниц, уверенность извлечения.
5. Экспорт XLSX-матрицы, ручная модерация, журнал решений и обезличенные тесты качества.
