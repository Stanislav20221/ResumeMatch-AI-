# ResumeMatch AI v0.6 — векторный поиск, эмбеддинги и RAG/FAISS

Это **дополнение к рабочей версии v0.5.1**. Существующие извлечение LLM, семантическая матрица, анализ стажа и обязанности не переписываются. RAG располагается отдельным блоком результатов основного анализа.

## Что реализовано

```text
PDF / DOCX / TXT (резюме)           Текст выбранной вакансии
              │                             │
              └───── Парсер / блоки ────────┘
                           │
        Чанкинг до 700 символов (+ 100 пересечения
           для слишком длинных исходных строк)
                           │
           OpenAI text-embedding-3-small
              (векторы 1536 измерений)
                           │
             L2-нормализация NumPy
                           │
                FAISS IndexFlatIP
            (косинусная близость, RAM)
                           │
    Вопрос → embedding вопроса → FAISS top-k (до 8)
                           │
     Найденные фрагменты + страницы + источники
                           │
        OpenAI Responses (gpt-4.1-mini по умолчанию)
                           │
     Структурированные claims + chunk_id + quote
                           │
      Проверка цитат по оригинальным блокам
                           │
          Ответ и проверяемые доказательства
```

Отдельные типы `resume` / `vacancy`, метаданные исходного поля, номера страниц PDF и индексы исходных строк. При поиске по двум документам учитываются фрагменты **обоих** источников; если требуется, до 3 результатов из каждого источника попадают в итоговый top-6.

Отдельная галочка согласия нужна **для отправки на генерацию эмбеддингов, поискового вопроса и фрагментов для RAG-ответа**. Каждый индекс временный, не выгружается на диск, удаляется по кнопке, при перезапуске сервера или после 20 минут. Для доступа используется случайный непрогнозируемый `session_id`. Не более 10 одновременных индексов на один рабочий процесс.

> **Не гарантия истинности.** `source_verified` означает дословное наличие цитаты, но не доказательство того, что утверждение LLM логически следует из неё. Результаты не влияют автоматически на итоговый балл и требуют проверки человеком.

## Установка (Windows PowerShell)

1. Убедитесь, что текущая версия проекта v0.5.1 работает и тесты проходят.
2. Распакуйте ZIP **в корень** `F:\MATRIX`, чтобы появились `app\rag.py`, `app\rag_api.py`, `scripts\install_rag_v06.py`, `tests\test_rag.py` и этот README.
3. В корне проекта выполните:

```powershell
cd F:\MATRIX
.\.venv\Scripts\python.exe scripts\install_rag_v06.py
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\check_faiss_v06.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

Установщик **делает резервные копии** затронутых `app/main.py`, `static/index.html`, `requirements.txt` и `.gitignore` в этих же каталогах с суффиксом `.before_rag_v06` и добавляет исключение для этих копий в `.gitignore`. При повторном запуске он не дублирует вставки. Не запускайте его вне корня проекта.

Новая страница: **http://127.0.0.1:8765/**. Новый Swagger: **http://127.0.0.1:8765/docs**.

## Проверка через интерфейс

1. Загрузите `samples/demo_resume_experience_positive.txt` и выберите режим демонстрационных вакансий.
2. Нажмите **«Проанализировать резюме»**.
3. В разделе **«Векторный поиск и RAG · FAISS»** выберите `Python Backend / AI-разработчик — проверка стажа`.
4. Разрешите отправку исходных текстов и запросов в OpenAI. **Это платные вызовы API.**
5. Нажмите **«Создать FAISS-индекс»**. Должны появиться число чанков, модель и размерность вектора.
6. Введите вопрос: `Какой опыт REST API и FastAPI подтверждается резюме и что требует вакансия?`
7. Нажмите **«Найти фрагменты»**, затем **«Спросить RAG (OpenAI)»**.
8. Проверьте цитаты, `r...` для резюме, `v...` для вакансии, номера страниц и первоисточники. Нажмите **«Удалить индекс»**.

При выборе другой вакансии / нового файла индекс сбрасывается.

## API

- `POST /api/rag/index` — multipart form: `resume` (PDF/DOCX/TXT), `vacancy_description` (строка), `vacancy_key_skills` (JSON-массив строк), `cloud_consent=true`. Возвращает `session_id`, размер индекса, модель и TTL.
- `POST /api/rag/search` — JSON `{ "session_id": "...", "question": "...", "top_k": 6, "scope": "both", "cloud_consent": true }` → найденные чанки и косинусная близость.
- `POST /api/rag/ask` — тот же JSON (область поиска всегда обе стороны) → структурированный ответ, проверенные цитаты, retrieval-контекст.
- `POST /api/rag/delete` — JSON `{ "session_id": "..." }` → освобождение индекса без LLM-запроса.

### Ограничения и безопасность

- Приложение рассчитано на **локальный запуск на 127.0.0.1**. Нет полноценной авторизации, разделения пользователей или распределённого хранилища сессий. **Не публикуйте API в интернет без защиты.**
- Данные держатся **в оперативной памяти конкретного Python-процесса**. Используйте один процесс Uvicorn; `--reload` перезапускает процесс и обнуляет индексы.
- Один индекс — до 100 тыс. символов суммарно, до 180 фрагментов, один запрос — до 700 символов, top_k 1..8.
- Эмбеддинги и контекст отправляются на OpenAI API с согласия пользователя; бесплатны только поиск FAISS после получения эмбеддинга и тесты с имитацией API. Фактические правила хранения данных у провайдера определяются его политиками.
- Ответы OpenAI запрашиваются с `store=False`. API эмбеддингов использует отдельный вызов и не имеет этого параметра.
- `faiss-cpu` устанавливается на Windows x64 Python 3.13 через `pip`; установка требует доступ к PyPI.
- Индексация **не меняет** существующий `score_percent`, матрицу навыков, расчёт стажа или результаты семантического анализа.
- Нет персистентности FAISS, инкрементальных обновлений, reranker, токенового бюджетирования на всё резюме или массового индексирования множества вакансий: это дальнейшие этапы.

## Тестирование

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_rag.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\check_faiss_v06.py
```

Новые офлайн-тесты используют `FakeFAISS` и `FakeOpenAI` и **не делают платных запросов**. `scripts/check_faiss_v06.py` выполняет проверку **реально установленной** библиотеки FAISS без OpenAI.

git status --short
